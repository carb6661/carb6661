# 网络安全作品集建设路线

以下未完成事项均为计划，不作为已掌握能力或实战经历展示。

## 优先补强已有项目

| 项目 | 计划 | 验收证据 |
| --- | --- | --- |
| Compliance RAG Assistant | 已完成结构化入库首版；下一阶段在原仓库补检索、版本过滤、引用与拒答，避免另建重复切分仓库 | 标题作用域、源码切片测试及结构修复对照；检索能力尚未实现 |
| RAGShield | 补充鉴权边界案例、HTTP 目标限制回归与示例报告 | 正反例测试、报告样本与局限说明 |
| Secret Scanner | 目录剪枝、规则白名单、JSON 输出、合成标注数据集 | 精确率/召回率的计算方法、回归测试与已知漏报 |
| Headers Auditor | 解析 HSTS/CSP/Referrer-Policy 语义与重复响应块 | 危险配置不再误判通过，附测试 |
| Integrity Monitor | 基线结构校验、错误处理与基线保护设计 | 畸形输入测试、变更复现与信任边界说明 |

## 独立项目方向与进度

1. SOC 日志分析：已发布 [Auth Log Triage](https://github.com/carb6661/auth-log-triage)，提供三条认证规则、合成样本、事件时间线、证据、36 项本地测试及误报/漏报实验。仅完成离线教学首版，后续可补授权格式适配与跨文件状态；不再重复新建同类阈值检测仓库。
2. 安全 API 实验：已发布 [RAG Document Authorization Lab](https://github.com/carb6661/rag-document-authz-lab)。0.2版增加严格JSON/关键头、有界请求、故障审计、会话容量与主体撤销、授权后关键词检索；16组对照、164项本地测试及五项旧版复现证据。下一阶段需选择真实身份/持久库并定义处理中撤销语义；未接入生产IdP/数据库/向量RAG，不另建重复BOLA实验。
3. 事件响应时间线：分析本地合成事件，解释时间戳、证据可信性和处置记录。
4. 安全配置审查：审查本地配置中的权限与危险选项，给出修复差异和回归验证。

## 后续项目发布标准

最新用户主线：继续建设 [Compliance RAG Assistant](https://github.com/carb6661/compliance-rag-assistant)，优先使现有项目具有实际使用价值。后续检索需保留级别/版本/安全类过滤，使用原创合成样本验证；不上传未获许可的标准全文，不把第一阶段解析当作完整测评系统。

- 明确岗位能力关联、风险场景、资产与信任边界。
- 提供可运行代码、中文 README、合成数据、复现实验、测试与许可证。
- 展示检测证据、修复建议和验证方法；说明误报、漏报与适用范围。
- 不虚构实战经历、测试结果、性能数字、用户量或认证。
- 课程方向选择支持安全能力的网络、操作系统或数据库主题，避免无关联的小练习。
